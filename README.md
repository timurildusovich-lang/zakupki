# Закупки — запрос прайс-листов через Codex

Проект помогает запрашивать у поставщиков сток и предзаказ, отслеживать ответы и напоминать о прайсах. Вы ставите задачу в чате Codex **«Запросить прайсы»**. Codex подбирает поставщиков, готовит письма и показывает их для подтверждения. История хранится в файлах проекта и отображается в [index.html](index.html).

## Быстрый старт

1. Откройте проект `D:\Проекты\Закупки` в приложении Codex и чат **«Запросить прайсы»**.
2. Напишите, какие бренды и виды прайса нужны. Например: **«Запроси сток Tigi»**.
3. Ответьте на уточнения Codex, если они появятся.
4. Проверьте отправителя, поставщиков, все адреса, темы и тексты писем. При необходимости попросите изменить их или исключить поставщика.
5. После проверки напишите явное подтверждение, например: **«Подтверждаю отправку показанных писем по указанным адресам»**.
6. Для просмотра результата напишите: **«Открой историю запросов»**.

В рабочем режиме подтверждение запускает отправку, если подключение почты проверено и сейчас рабочее время. В локальной симуляции оно создаёт только тестовые записи.

**Если адреса или текст изменились, нужно проверить новый вариант и подтвердить его заново.** Подключение почты само по себе не разрешает отправку нового запроса.

### Если вы скачали проект с GitHub

В репозитории есть код, инструкции, настройки и вымышленные тестовые данные. Пароли, рабочий справочник с контактами, переписка, вложения и сформированный `index.html` остаются локальными и в Git не входят.

1. Откройте скачанную папку как проект в Codex. Если папка находится по другому пути, используйте его вместо `D:\Проекты\Закупки` в примерах команд.
2. Для локальной демонстрации выполните `.\run.ps1 --env test demo`, затем `.\run.ps1 report`. Появится `index.html` с тестовой историей.
3. Для рабочей среды попросите Codex прочитать исходную Google-таблицу через ваше подключение, сохранить `data/source-sheet.json` и выполнить `import-catalog`. Это создаст `data/catalog.json`; до этого команды рабочей среды не смогут прочитать справочник.
4. Скопируйте [.env.example](.env.example) в `.env` и настройте почту по разделу ниже. Подключение Google Drive и фоновую автоматизацию настройте в своём приложении Codex — они не переносятся вместе с Git.

Состояние готовности ниже относится к исходному компьютеру. На новом компьютере подключения нужно проверить заново; настройка `mode: live` сама по себе их не создаёт.

## Как сформулировать запрос

Точная команда не обязательна: Codex распознаёт намерение по смыслу.

| Ваше сообщение | Что будет запрошено |
|---|---|
| «Запросить прайс-листы Tigi» | Codex уточнит: сток, предзаказ или оба вида |
| «Запроси сток Tigi» | Сток Tigi у участвующих поставщиков этого бренда |
| «Нужен предзаказ Davines» | Прайс предзаказа Davines |
| «Запроси сток и предзаказ Davines и Tigi» | Оба вида для двух брендов; бренды одного поставщика объединяются в одно письмо |
| «Запроси сток всех брендов» | Сток по общему списку брендов справочника |

Если бренд не указан или отсутствует в справочнике, Codex задаст вопрос. Можно вставить текст письма с запросом — бренды будут извлечены из него.

Перед рабочей отправкой Codex обновляет справочник и проверяет, есть ли уже свежие прайсы в почте и на Google Drive. Свежие позиции и позиции, по которым уже ожидается ответ, повторно не запрашиваются. Неполная проверка или неопределённая дата прайса требуют уточнения.

Письма составляются на языке поставщика из справочника. Сейчас подпись не добавляется. Объёмы заказа, целевые цены и обещания покупки нужно сообщать отдельно: Codex их не придумывает.

## Где находятся бренды и адреса поставщиков

Основной источник — [Google-таблица «Поставщики Европа — почта»](https://docs.google.com/spreadsheets/d/1-yQBQXjbKm8dXp_9Et4_GP2SQnS35DA4pOvx2U4nBKM/edit?gid=0#gid=0), вкладка **«Лист1»**.

В таблице указаны номер поставщика, язык, названия, контактные имена, email и бренды. Локальные файлы:

- [data/source-sheet.json](data/source-sheet.json) — сохранённые исходные значения таблицы.
- [data/catalog.json](data/catalog.json) — рабочий справочник: у каждого поставщика есть список email и брендов.
- [config/catalog-resolutions.json](config/catalog-resolutions.json) — подтверждённые правила чтения объединённых ячеек и дополнительных контактов.
- [data/catalog.test.json](data/catalog.test.json) — отдельные вымышленные поставщики для симуляции.

Подтверждённые правила: общий список в `G2:G20` относится к поставщикам №1–15; у Тубы — Kydra и Gehwol, у Комаира — Refectocil. Дополнительные email относятся к тому же поставщику. **«Алексей прайсы (дубли)» исключён из запросов.** Слово `Stock` означает сток всех брендов, а не отдельный бренд.

Чтобы изменить рабочие контакты, обновите исходную Google-таблицу и попросите Codex перечитать справочник. Перед рассылкой проверьте показанные адреса. Ручная правка локального снимка может быть заменена при следующем обновлении из таблицы.

## Ответы и напоминания

- Сток считается актуальным **7 дней**, предзаказ — **один календарный месяц**.
- Дата прайса в почте берётся по времени получения письма. На Диске используется дата папки; если указан только месяц, точный день не выдумывается.
- Проверенный прайс во вложении или ссылка на него прекращает напоминания по полученным позициям. Частичный ответ закрывает только соответствующие бренды и виды прайса.
- Вопрос поставщика об объёме заказа или целевых ценах появляется в чате Codex. Он не считается полученным прайсом; коммерческий ответ требует ваших данных и указания.
- После первого письма предусмотрено **до 5 напоминаний**, всего до 6 сообщений. Темы и тексты меняются.
- Интервал — следующий рабочий день в то же время: **пятница 15:00 → понедельник 15:00**.
- Отправка выполняется **с понедельника по пятницу, с 09:00 до 19:00 по Москве**; в 19:00 окно уже закрыто. С **31 декабря по 7 января включительно** действует перерыв. Остальные праздники отдельно не исключаются.
- После пятого напоминания даётся ещё один такой же интервал на ответ. Если прайс не получен, Codex сообщает поставщика, email и итоговый статус.

Попросите Codex **«Поставь напоминания по этому запросу на паузу»**, если переписку нужно приостановить. Уточните запрос и поставщика, если активных запросов несколько.

Фоновая проверка предусмотрена встроенной автоматизацией Codex каждые 15 минут в рабочее время. **Для неё нужны включённый компьютер и работающее приложение Codex.** Сейчас она на паузе. После пропущенного запуска серия накопленных напоминаний подряд не отправляется.

## Где сохраняются полученные файлы

Вложения сначала сохраняются локально в `data/<среда>/attachments/` с оригинальными именами. Поддерживаются **XLS, XLSX, CSV, PDF, ZIP, RAR**, максимальный размер одного вложения — **50 МБ**.

Рабочая загрузка предусмотрена в [папку прайсов Google Drive](https://drive.google.com/drive/folders/1I_AjRCFe2YSVsESxpq9v3Io60cNQZa_J) с сохранением существующей структуры: категория → бренд → поставщик → год → датированная папка. Codex загружает файл через подключение Google Drive, проверяет результат и сохраняет ID и ссылку в истории. Локальный движок создаёт задания на загрузку; самостоятельно Google Drive он не авторизует.

**Пока запись на Google Drive выключена.** Пароль Google в `.env` не нужен: авторизацией управляет подключение Google Drive в Codex. Если соединение истечёт или папка не разрешает запись, потребуется переподключение или доступ к папке.

Для прайса с несколькими брендами папку выбираете вы. До решения файл остаётся локально. Файлы почтового теста на рабочий Диск не загружаются.

## История

Напишите **«Открой историю запросов»** — Codex откроет [index.html](index.html) в своей панели. Файл также можно открыть обычным браузером, без сервера.

История содержит запросы, поставщиков, адресатов, исходящие письма, ответы, напоминания, файлы, ссылки и статусы. Среды отображаются отдельно:

| Среда | Назначение | Файл состояния |
|---|---|---|
| `test` | Полностью локальная симуляция без сети | `data/test/state.json` |
| `mail_test` | Настоящие тестовые письма только на Gmail пользователя | `data/mail_test/state.json` |
| `live` | Рабочие запросы поставщикам | `data/live/state.json` |

Рабочая история создаётся по мере работы. Тестовые события и подтверждения не переносятся в неё.

HTML — снимок истории. После новых событий его нужно сформировать командой `report` и обновить открытый просмотр. Обычно это делает Codex. Для переноса или резервной копии проекта сохраняйте каталог `data` целиком: одного `index.html` недостаточно для продолжения переписки.

## Подключение рабочей почты

Этот раздел нужен тому, кто настраивает проект. Для обычных запросов достаточно чата.

1. Получите **пароль для внешнего приложения** рабочего ящика Mail.ru.
2. В локальном файле `.env` в корне проекта добавьте отдельные рабочие переменные:

   ```dotenv
   PRODUCTION_EMAIL_LOGIN=tam_sabis4@mail.ru
   PRODUCTION_EMAIL_PASSWORD=<пароль внешнего приложения рабочего ящика>
   ```

   Значение в угловых скобках — место для вашего пароля, а не готовый пароль. Тестовые `EMAIL_LOGIN` и `EMAIL_PASSWORD` принадлежат ящику `timur-ildusovich@mail.ru`; их можно сохранить.

3. Напишите Codex: **«Данные рабочего ящика добавлены в .env, проверь подключение»**.
4. Codex выполнит `--env live mail-check`. Команда проверяет SMTP и IMAP, не отправляет письма и не читает содержимое старых сообщений.
5. После успешной проверки Codex завершит подготовленный переход и включит фоновую автоматизацию. Каждый новый запрос прайсов по-прежнему требует просмотра и подтверждения.

Пароли не присылайте в чат. `.env` исключён из Git; секреты не должны попадать в историю, HTML и документацию. Разрешение на переход в рабочий режим уже получено. Загрузка на Google Drive проверяется и включается отдельно.

Повторный настоящий почтовый тест попросите подготовить у Codex: он требует отдельной настройки режима `mail_test`. Его согласованный маршрут — **`timur-ildusovich@mail.ru` → `timurildusovich@gmail.com`**.

## Полезные команды PowerShell

Запускайте из корня проекта. `run.ps1` выбирает Python из комплекта Codex; при его отсутствии нужен Python 3.12+ или путь к нему в переменной `PURCHASES_PYTHON`.

```powershell
Set-Location -LiteralPath 'D:\Проекты\Закупки'

# Проверить состояние рабочего окружения без отправки писем
.\run.ps1 --env live doctor

# Проверить вход в рабочую почту после заполнения .env
.\run.ps1 --env live mail-check

# Сформировать HTML-историю
.\run.ps1 report

# Запустить демонстрацию на вымышленных данных, без сети
.\run.ps1 --env test demo
```

Без `--env` команды используют среду **`test`**, даже если в настройках выбран `mode: live`. Демонстрация записывает тестовую историю; повторный запуск сохраняет уже существующую. Команды подготовки, подтверждения, отправки и разбора ответов описаны в [docs/cli.md](docs/cli.md); при обычной работе их выполняет Codex.

## Если что-то не получается

| Ситуация | Что сделать |
|---|---|
| Codex спрашивает вид прайса | Укажите «сток», «предзаказ» или «оба» |
| Рабочая отправка заблокирована | Проверьте рабочие переменные `.env`, затем попросите выполнить `--env live mail-check` |
| Mail.ru отклоняет вход | Проверьте логин и пароль внешнего приложения именно выбранного ящика |
| Запрос пропущен как свежий или уже активный | Посмотрите причину в предпросмотре или попросите Codex показать существующий прайс/запрос |
| История не показывает новые события | Попросите обновить историю или выполните `report`, затем обновите просмотр |
| Файл ждёт выбора папки | Укажите Codex нужную папку Google Drive |
| Напоминание не пришло вовремя | Проверьте паузу автоматизации, рабочий календарь и работу приложения Codex |
| Результат отправки неизвестен | Попросите Codex сверить отправку с почтой перед повтором |
